# 本轮新增功能操作说明

## 日常跟进

新增“是否固定靶”关联跟进周期，默认固定靶 7 天、非固定靶 14 天，到周期当天提醒；仅未中标活动项目参与。在项目管道点击“只看需跟进”可跨页筛选。周期在“配置 → 跟进提醒”调整，项目级别独立选择无风险、低风险、高风险或未设置，不改变周期。详见 [跟进提醒说明](FOLLOW_UP_REMINDERS.md)。

项目编辑可填写“下次行动日期”和内容。项目管道默认按逾期、今天、未来、未安排排序，在后端分页前完成；可使用逾期、今天、未来 7 天、未安排筛选，也可自行选择其他排序。

逾期显示红框及天数，今天深橙、明天橙、2—7 天浅黄。普通编辑不会取消提醒，使用“完成本次行动”清空日期或安排下一次。日期统一为 Asia/Shanghai，跨日和窗口重新获得焦点时刷新。

“最后跟进时间”只读。项目字段、方案、产品、责任人、进展、收入确有变化才更新；历史进展日期仍是原业务日期。旧项目从历史业务记录回填，不统一设为升级当天。

## 导入和日期纠错

1. 选择 Excel/CSV，解析在浏览器 Worker 中进行；原始文件不上传，确认后的结构化记录会发送后端并保存到任务中。
2. 可选择 HCS/公有云作为空赛道默认值。缺年进展需填写“进展默认年份”，不填则待修正。
3. 现有字段优先匹配，未匹配列建议新增，名称和类型可修改；预检不创建字段，只有正式导入成功行使用的字段才创建。
4. 支持 `2026-09-13`、`2026/9/13`、`2026.9.13`、`2026年9月13日`，以及有明确默认年份的 `9月13日`、`09/13`。无日期续行并入当前进展并保留换行。首段无日期或 `2026-02-30` 等非法日期不使用当天兜底。
5. 同一目标的多列值冲突进入待修正，不静默覆盖。补客户、改标准值、批量纠错、排除行、只导入通过项继续可用。
6. 确认后可在右下“后台任务”查看进度和逐项结果。刷新不丢后端任务；失败项可重试，成功项不重做。

历史错误进展在“配置 → 历史进展修复”分页预览。能从原文确定完整有效日期才建议修正；其他记录须人工核对原文件，填写日期、内容和依据。并发变化会要求重新预览，原录入时间不改变。

## 赛道、字典和产品

赛道仅 HCS、公有云；历史数据安全/云安全等迁入“安全方向”，业务赛道待分类并列出迁移异常，不猜测。切换赛道不会清除隐藏字段。自定义字段可配置适用赛道，不选择表示公共；新导入扩展字段默认公共，可随后配置。

映射、模板可保存适用赛道，列表列偏好按赛道分别保存。跨赛道导出使用字段并集。公有云固定映射保留云空间、安全月度空间、预计下单时间、一线 SA 原文等独立口径；风险和求助全部保留。来源没有项目名称需补齐，不能自动用客户名代替。

“配置 → 产品目录”支持新增、改展示名、别名、排序、赛道和启停。编码不能修改，改名不改变引用。停用后禁止新增选择，原记录及旧模板仍可查看和导出。方案树是推荐关系，项目已购是独立拥有关系，换方案不会清空产品。

仅明确已购列使用非空即已购规则。`需求洞察/WAF` 等保留为需求扩展字段，不代表已购。别名只识别产品，不推断是否购买。

## 多方案与责任人

表单可增加多组方案，每组可选多个细分，重复关系去重。中标至少一组完整有效方案/细分及一个已购产品。旧单方案模板仍可导入；新模板“方案集合（JSON）”保留父子关系：

```json
[{"solution":"实际一级方案","subSolutions":["其下细分一","其下细分二"]}]
```

统计各方案分别计数，同组及一级汇总按项目去重，全局不重复；不分摊收入。点击统计可下钻。

“配置 → 责任人库”维护姓名、工号、账号、确认别名和启停，支持 Excel/CSV 预览后导入。项目可选多名手工责任人。优先工号/账号，缺标识才用唯一姓名/已确认别名；歧义不猜测。HCS/手工来源分别保留。真实同步尚未启用。

## 批量、导出和永久删除

批量删除/恢复/永久删除使用后端任务，一次最多 5000 个，单项失败不回滚其他项目。每批 100 条、最多并行 2 个。唯一请求标识避免重复提交；重启标为中断，重试只执行尚未成功项。

综合导出每项目一行，收入按月分列，进展为带日期文本，产品按目录拆列，方案集合为 JSON。后端分块读取，Worker 生成 Excel，任务中心可再次下载。

永久删除仅限回收站且有确认。业务关联及旧任务原文/快照一并清理；无法单独识别的导出分块整块失效，先重试剩余项目再下载，不悄悄下载缺行文件。旧任务不能重建项目；确需重新创建可发起新导入请求。已下载文件及库外备份需自行处理。

## 升级、备份与恢复核对

升级前备份 MySQL；保留历史 Flyway 文件，按 V7—V15 迁移（V15 新增固定靶、项目级别和跟进周期）。先在隔离库验证再升级实际库；异常方案/赛道列出项目和原值，人工处理。不要删除旧迁移或使用 `ddl-auto=create` 覆盖业务库。

JSON 备份覆盖新目录、关系、人员、任务及清理标记。只读预检：

```bash
node scripts/validate-backup.mjs /绝对路径/backup.json
```

脚本核对主键、外键、方案父子、产品、任务 JSON、收入总额，不写库、不自动恢复 JSON。实际恢复沿用 `ops/backup/restore.sh` 的显式确认 SQL 恢复。先恢复隔离库，再核对项目数、方案关联数、产品拥有数、月收入总额、任务及清理标记。不要直接在现用库试恢复；本轮未替用户执行恢复。

三份模板位于 `docs/deliverables/`：统一字段对照表、公有云导入模板、HCS 本地项目模板。模板示例行须替换或删除，不是实际业务数据。
